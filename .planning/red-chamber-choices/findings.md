# 发现与决策

## 需求

- 选角后在该角色的地图上按顺序进入场景，完成一个场景即点亮节点并解锁下一站。
- 选项改变下一站的实际对话，末站给出可解释评分、结局分类和对应徽章。
- 小工具作为现有 pnpm 工作区的独立应用。

## 人选与原著场景

新浪在 2005 年发起的开放投票中，黛玉、宝钗、湘云、熙凤、探春均位于前列。该投票可作候选参考，样本为自愿参与，时间跨度长。本轮未找到可用的近期代表性人气榜，首发取舍还考虑叙事辨识度和制作规模。[新浪投票原始结果](https://survey.news.sina.com.cn/print.php?dpc=1&pid=1146)

拟采用《红楼梦》程甲本定位回目。以下为选段及拟写的玩家取舍，场景顺序沿小说回目。[程甲本目录](https://zh.wikisource.org/zh/紅樓夢（程甲本）/紅樓夢目錄)

| 角色 | 时间线节点 | 可写的选择张力 |
| --- | --- | --- |

| 薛宝钗 · 首发 | 8 金锁通灵 → 27 滴翠亭扑蝶 → 42 兰言劝黛玉 → 56 议园中改革 | 礼数、人情和实际安排如何兼顾，尤其是消息可能牵连旁人时怎么开口 |
| 王熙凤 · 首发 | 6 刘姥姥初进荣国府 → 13 协理宁国府 → 15 铁槛寺事 → 68–69 尤二姐入园及余波 | 施援、立规、权力边界及其对他人的影响 |
| 史湘云 · 后续 | 50 芦雪亭联诗 → 62 醉眠芍药裀 → 70 填柳絮词 → 76 凹晶馆联诗 | 畅言、幽默、失意时如何回应友人 |

地图以可读的地点图标、连线和回目标示进程。对各角色共用的事件复用地点与背景，角色视角、选项和后果分别编写。游戏尾声回顾这一局的关系变化和玩家选择。

## 分支样例

下面是黛玉线的改编提纲。第二站花冢收束后，第三站都来到潇湘馆，宝钗的第一段话因黛玉选择而变。采用原著中的葬花和宝黛钗关系作素材，新增的转述和台词属于游戏改编。[第二十七回](https://zh.wikisource.org/wiki/紅樓夢/第027回) · [程甲本第四十五回](https://zh.wikisource.org/wiki/紅樓夢（程甲本）/四十五) · [程甲本第七十六回](https://zh.wikisource.org/wiki/紅樓夢（程甲本）/七十六)

| 第二站选择 | 第三站变化 | 记分 |
| --- | --- | --- |
| 托紫鹃转告宝钗，夜里愿谈谈 | 宝钗应约，主动问起花冢的心事 | 顾情 +2，护己 +1 |
| 请紫鹃守口，把心事留给自己 | 宝钗来探病，察觉黛玉的犹疑，先问她愿不愿意说 | 护己 +2，谋事 +1 |
| 把散落的花收妥，请人转告园里避踩新土 | 宝钗从园中消息得知她的安排，先说起花冢的后续 | 谋事 +2，顾情 +1 |

第三站保留共同的探病与夜谈情境，再让玩家作出新选择。第四站可用一句回扣提及此前玩家是否在花冢主动传话，末站选择直接影响游戏尾声。

## 评分与徽章

- 每次确认选择给主维度 2 分、次维度 1 分。四站通关后共 12 个原始分，单维上限 8 分。结算页分别显示护己、顾情、谋事三项分数（原始分 ÷ 8，换算为百分制），并回顾两次造成明显后果的选择。
- 最高与次高原始分差 1 分以内，结局为兼顾型，获得「袖纳清风」。其余按最高维度分类，护己对应「一枝自持」，顾情对应「金兰知心」，谋事对应「落子有方」。
- 徽章按角色收集，每局发放一枚。徽章与分类描述当局的回应方式。通过枚举确认可达性，发现某枚徽章无法达成时调整具体选项权重。
- 例如护己 6、顾情 4、谋事 2 时，显示 75、50、25，并授予「一枝自持」。护己 5、顾情 4、谋事 3 时发放「袖纳清风」。

## 技术决策

| 决策 | 理由 |
| --- | --- |
| 时间线节点对应固定场景 ID，选择对应稳定选项 ID | 可从存档重建对话和计分，并做分支遍历 |
| 将立即生效的对话条件与跨站回扣拆开 | 下一站有明确反馈，少量早期选择能留下长期影响 |
| 地图和剧情文案随离线产物打包 | 地图、选项、结算不依赖远程素材或生成服务 |

## 遇到的问题

| 问题 | 解决方案 |
| --- | --- |
| 近期人气缺少代表性数据 | 记录开放投票的时间口径，使用角色辨识度和路线差异确定首发 |
| 全部历史选项组合都会触发新台词时，文本规模快速扩大 | 三种来路对应下一站开场，正文归并到共同情境，仅为关键选择写跨站回扣 |

## 原型实施时的容器核验

在线清单列明 Android 10+、iOS 18.4+，Android 产物仍需兼容 ES2017 和 Chrome 61。原型使用 9.46.0 起支持的容器 Storage，按 buildVersion 去掉构建号判断客户端版本。缓存不可用时体验当前一局，读档失败时避免覆盖旧进度。地图连线使用 Canvas 2D，JS 采用经典外置脚本。园景及人物插画作为 WebP 随包提供。[平台能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)

## 纸艺场景改版规格

- 场景依次为荣府朱门、送花花冢、竹院雨窗与中秋水榭。沿同一张 2D 折页地图进入，玩家主要点击地标和阅读框。
- 纸张采用细纤维米杏底 `#e1d4ad`、赭朱 `#9d4e39`、竹青 `#52715a`、胭脂 `#b56f6b`、湖蓝 `#577a80`、夜靛 `#263b50`、墨褐 `#453529`。物件使用 3 至 5 层色纸，薄切边约 2 像素，草木有窄的十字插片。
- 相机为 Canvas 2D 约 43° 俯视的纸模投影，暖光由左上 50° 落下、前方约 1/3 补光。阴影白天为暖褐、秋夜为靛青。主要地标集中在画面中部 40% 的清晰带，前沿用岩石、竹叶及水岸纸层遮入。
- 适配 9:16 手机与横屏，场景局部不裁掉当前可交互节点。纸模从铰线翻起，约 0.72 秒内越过直立并回稳，分组错开约 60 毫秒。落花、斜雨、萤点分别服务于相应场景，系统减少动态时停用。
- 按手机 390×844、短屏和桌面分别检查地图、地标状态、独立场景、长对话、选项及结算；持续验证离线构建。沿用容器 Canvas 2D 和 Storage，二者在线契约与上轮一致。
